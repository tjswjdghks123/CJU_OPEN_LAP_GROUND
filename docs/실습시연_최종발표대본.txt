센서 10개 기반 LSTM 실습 시연 — 최종 발표 대본

사용법: [대괄호]는 화면에서 할 행동입니다. 대괄호를 제외한 문장은 그대로 읽으면 됩니다.
현재 ground.py 기본 시연 기준. 약 6~8분 분량이며 화면 재생 대기 시간에 따라 달라집니다.


[1. 프로그램 실행 후 화면 열기]

안녕하세요. 이번 과제에서는 센서 10개의 시간에 따른 변화를 입력받아, LSTM 모델이 점수를 계산하고 시험 경보를 표시하는 프로그램을 구현했습니다.

현재는 실제 회사 장비와 연결한 상태가 아니라, 직접 만든 합성 데이터로 동작을 확인하는 단계입니다. 오늘은 입력 처리, 모델의 점수 계산, 경보 표시와 반복 평가 결과를 보여드리겠습니다.


[2. 센서 입력 표 가리키기]

입력은 대지전위 a와 b, 누설전류, 제한소자 온도 a·b·c, 상대습도, 외기온도, 입력전압, 낙뢰 누적 발생 횟수로 총 10개입니다.

입력 항목과 측정 주기는 제공받은 센서 표를 참고했습니다. 장비 사진은 장비 구성과 통신 설정을 이해하는 데 참고했습니다. 하지만 실제 데이터의 순서와 변환 배율, 통신 명세를 확인하지 못해서 실제 장비 연결은 하지 않았습니다.

장비 상태 기준은 전달받은 값에 따라 대지전위 각각 2볼트, 누설전류 2밀리암페어, 제한소자 온도 각각 45도로 설정했습니다. 습도 70%와 외기온도 25도는 환경 참고 기준이며, 입력전압에는 임의의 경보 기준을 추가하지 않았습니다. 누설전류 2밀리암페어는 프로그램에서 0.002암페어로 처리합니다.

이 기준들은 장비 상태를 확인하는 기준입니다. 기준을 넘었다고 실제 낙뢰가 발생한다는 의미는 아닙니다.


[3. 정상 상황 선택 — 최근 기록을 설명하기]

먼저 정상 상황입니다.

시연에서는 1초마다 센서 10개의 값을 한 줄씩 기록합니다. 측정 주기가 긴 센서는 새 값이 갱신되기 전까지 이전 값을 유지합니다.

센서마다 단위와 값의 크기가 다르므로, 학습 데이터에서 구한 Min-Max 기준으로 값을 변환합니다. 새로운 입력이 들어올 때마다 정규화 기준을 다시 정하는 것은 아닙니다.

모델은 최근 30개 시점의 기록을 한꺼번에 봅니다. 예를 들어 100초의 점수는 71초부터 100초까지의 센서 기록으로 계산합니다. 다음 101초에는 72초부터 101초까지의 기록을 사용합니다.

한 번의 판단에는 30개 시점과 센서 10개로 구성된 숫자 300개가 사용됩니다. 현재 값 하나만 보는 것이 아니라, 최근에 어떻게 변했는지를 함께 보는 방식입니다.

전체 시연은 0초부터 179초까지입니다. 179초는 전체 재생의 마지막 시각이고, 그때의 점수는 150초부터 179초까지의 기록으로 계산합니다. 처음에는 기록을 모으기 때문에 점수가 바로 나오지 않습니다.


[4. 파란 선과 빨간 점선 가리키기]

파란 선은 매초 입력 기록으로 계산한 LSTM 점수입니다. 마지막에 시그모이드 함수를 사용해서 0과 1 사이의 값이 나옵니다.

빨간 점선은 약 0.9744로 설정된 경보 기준입니다. 점수가 이 기준 이상이면 시험 경보를 표시합니다.

점수가 0.99라고 해서 실제 낙뢰 발생 확률이 99%라는 뜻은 아닙니다. 현재는 합성 데이터로 학습한 패턴에 대한 점수입니다. 반대로 점수가 낮아도 실제 현장이 안전하다고 보장할 수는 없습니다.

또한 화면 위쪽의 현재 점수는 재생 위치의 점수입니다. 재생이 끝났을 때 보이는 낮은 점수가 그래프 전체의 최고 점수라는 뜻은 아닙니다.


[5. 과열 상황 선택]

다음은 과열 상황입니다.

제한소자 온도는 낙뢰가 없어도 올라갈 수 있습니다. 그래서 장비 기준 초과와 모델 경보를 따로 표시했습니다.

온도가 기준을 넘으면 장비 상태 기준 초과로 표시할 수 있지만, 이것만으로 낙뢰 전조라고 판단하지는 않습니다. 이 화면에서는 장비 기준값 비교와 LSTM의 패턴 판단이 서로 다른 기능이라는 점을 확인할 수 있습니다.


[6. 입력 모음에서 기존 보고서 시연 선택 → 가상 전조 패턴 선택 → 처음부터 재생]

다음은 기본 가상 전조입니다.

가상 전조는 사건이 발생하기 전에 대지전위 두 개와 누설전류가 함께 증가하도록 개발용으로 만든 패턴입니다. 실제 낙뢰 현장에서 관측한 전조를 그대로 가져온 데이터는 아닙니다.

여기서 사람이 정한 것은 데이터 생성 규칙과 가상 사건 시각입니다. 모델은 사건 시각을 입력받지 않고, 센서 10개의 최근 기록으로 점수를 계산합니다.

주황색 영역은 우리가 정한 가상 사건 직전 10초입니다. 모델이 위험 구간을 찾아서 색칠한 것이 아니라, 경보가 목표 시간 안에 발생했는지 비교하기 위한 정답 구간입니다. 세로선은 가상 사건 시각입니다.

파란 선은 미리 그려 놓은 그림이 아니라, 저장된 모델이 입력값으로 계산한 결과입니다. 다만 모델이 배운 전조 자체가 우리가 설정한 합성 규칙이므로, 이 결과를 실제 낙뢰 위험을 발견한 것으로 해석하면 안 됩니다.

정확히 말하면 우리가 설정한 합성 패턴을 모델이 사건 전에 찾아내는지 확인하는 시험입니다.


[7. 낙뢰 누적 횟수와 이번 시연 새 감지 표시 가리키기]

낙뢰 누적 횟수는 모델에 들어가는 입력 중 하나입니다. 시작값 1,000은 임의로 정한 카운터 기준값이며, 실제 낙뢰를 1,000번 관측했다는 뜻은 아닙니다.

프로그램은 누적 숫자 자체보다 이전 값에서 얼마나 증가했는지를 계산하고, 증가량에 log1p 변환을 적용합니다. 쉽게 말하면 큰 증가량의 크기를 줄여서 처리하는 변환입니다.

화면의 이번 시연 새 감지 1회는 입력 카운터가 한 번 증가했다는 뜻입니다. 모델이 사전 예측에 한 번 성공했다는 뜻은 아닙니다.


[8. 아래의 여러 난수 시드 평가 그래프 보여주기]

특정 데이터 하나에서만 되는지 확인하기 위해, 학습에 사용하지 않은 난수 시드 묶음 30개로 추가 평가했습니다.

난수 시드는 합성 데이터를 만드는 번호입니다. 같은 번호를 쓰면 같은 데이터가 만들어지고, 번호를 바꾸면 잡음이나 사건 발생 시각 등이 달라집니다.

한 묶음에는 정상, 과열, 누설전류 증가, 전압 급변, 가상 전조의 다섯 가지 상황이 있습니다. 기본 평가에는 30묶음, 총 150개 상황을 사용했습니다. 약한 전조 30개를 추가해서 전체 평가 상황은 180개입니다.

평가할 때 모델을 다시 학습하지 않았고, 저장된 모델과 동일한 경보 기준을 유지했습니다.

첫 번째 그래프는 가상 사건 시각을 0초로 맞춘 점수 곡선입니다. 0초 왼쪽은 사건 전, 오른쪽은 사건 후입니다. 기본 패턴과 약한 패턴에서 점수가 어떻게 다른지 비교합니다.

두 번째 그래프는 사건별 감지 결과입니다. 기본 가상 전조는 30건 모두 사건 전 10초 안에 경보가 한 번 이상 발생했습니다. 약한 전조는 30건 모두 이 조건을 만족하지 못했습니다.

세 번째 그래프는 전조가 없는 상황의 경보 여부입니다. 정상, 과열, 누설전류 증가, 전압 급변의 총 120건에서는 경보가 없었습니다.

하지만 전체 평가 시간에 오경보가 전혀 없었다는 뜻은 아닙니다. 전조가 있는 일부 상황에서는 목표 10초 구간보다 일찍 경보한 시점이 총 6개 있었고, 이것은 초 단위 평가에서 오경보로 따로 계산했습니다.

네 번째 그래프는 기본 패턴을 얼마나 먼저 경보했는지 보여줍니다. 사건 8초 전이 1건, 9초 전이 8건, 10초 전이 21건입니다. 이것은 정답 구간 안에서 처음 발생한 경보를 기준으로 계산한 값입니다.

사건 30건을 모두 잡았다는 것과 매초의 판단이 전부 맞았다는 것은 다릅니다. 기본 평가의 초 단위 재현율은 약 96.67%였습니다.

새 난수라도 같은 합성 규칙에서 만든 데이터이므로, 이 결과는 실제 낙뢰 성능이 아니라 합성 규칙 안에서의 반복 평가 결과입니다.


[9. 입력 모음에서 새 난수 · 약한 패턴과 잡음 증가 선택 → 가상 전조 패턴 재생]

약한 조건에서는 전조 증가 폭을 기본의 60%로 줄이고, 잡음을 두 배로 늘렸습니다. 잡음은 센서값에 섞이는 불규칙한 흔들림입니다.

화면처럼 파란 선이 올라갈 수 있습니다. 즉, 모델이 입력 변화에 반응한 것은 맞습니다. 하지만 경보 기준을 넘지 못해서 사전 경보 성공으로 집계되지 않았습니다.

감지 0건은 점수가 전부 0이라는 뜻이 아니라, 사건 직전 10초 안에 경보 기준을 넘은 사건이 없었다는 뜻입니다.

이 결과는 약하고 잡음이 많은 패턴에서의 한계를 보여줍니다. 신호 크기와 잡음을 동시에 바꿨기 때문에 어느 조건이 얼마나 영향을 줬는지는 각각을 따로 바꿔 추가로 확인해야 합니다.

경보 기준을 낮추면 더 많은 패턴을 잡을 수도 있지만, 정상 상황에 잘못 경보하는지도 함께 평가해야 합니다.


[10. 마무리]

이번 과제에서는 센서 10개의 입력 처리부터 최근 기록 구성, LSTM 추론, 시험 경보 표시, 여러 합성 조건에서의 평가까지 연결했습니다.

현재 화면은 실행할 때 계산한 결과를 브라우저에서 재생하는 방식입니다. 실제 회사 장비에서 데이터를 실시간으로 받고 있거나, 장비에 제어 명령을 보내는 상태는 아닙니다.

현재 확인한 것은 우리가 설정한 합성 패턴을 찾아내는 능력입니다. 기본 패턴에서는 동작했지만 약한 패턴에서는 경보에 실패했고, 실제 낙뢰 예측 능력은 아직 검증하지 못했습니다.

앞으로 실제 센서 기록과 별도로 확인된 낙뢰 발생 시각과 위치 기록을 확보해야 합니다. 이를 이용해 학습하고, 새로운 실제 데이터에서 감지율, 오경보와 사전 경고 시간을 평가해야 합니다. 장비 제어와 실제 보호 효과 역시 별도로 검증해야 합니다.

이상으로 시연을 마치겠습니다.

질문: 결국 사람이 만든 규칙을 학습한 것 아닌가요?
답변: 맞습니다. 입력의 생성 규칙은 사람이 정했고, 모델은 그 패턴을 학습했습니다. 점수 자체는 모델 계산 결과지만, 실제 낙뢰 예측 능력이 입증됐다는 의미는 아닙니다.

질문: 약한 패턴은 아예 반응이 없나요?
답변: 아닙니다. 점수가 올라가더라도 경보 기준에 도달하지 못하면 감지 성공으로 집계하지 않습니다.

질문: 실제 장비에 연결하면 바로 쓸 수 있나요?
답변: 연결하면 실제 입력을 받을 수 있지만, 성능이 자동으로 확보되지는 않습니다. 실제 기록과 낙뢰 정답으로 별도 학습과 평가가 필요합니다.

답변: 입력 구성은 제공받은 센서 표와 이후 전달받은 장비 기준값을 반영했고, 사진은 장비와 통신 설정을 이해하는 데 참고했습니다. 관련 연구와 공개 기상자료는 연구 방향을 검토하는 별도 실험이었으며, 현재 10개 입력 시연의 전조 패턴을 실제 관측으로 검증해 주는 근거는 아닙니다. 공동 상승 패턴과 카운터 시작값은 개발용으로 설정했습니다.

기억할 문장:
